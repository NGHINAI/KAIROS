# Act Mode — KAIROS computer use (2026-06-11)

User greenlit pulling Phase H's actuation forward: "ok lets add cua, and make it
truly better. and amazing." This is the Cua/HeyClicky pattern implemented natively
in our own sidecar — we already had the perception half (read_screen/AXFinder
numbered inventory = Cua's element_index); this adds the actuation half.

## The contract (better than HeyClicky's in two ways)

1. **AXPress-first**: `AXUIElementPerformAction(kAXPressAction)` asks the target
   app to press its own element via the Accessibility protocol (VoiceOver's path).
   No synthetic events, no cursor movement, no focus steal, works on sidebar rows
   that ignore synthetic clicks. HeyClicky leads with CGEvent; we use their event
   path only as fallback.
2. **Confirm gate on the RESOLVED label, pre-press**: DANGEROUS_LABEL_RE
   (delete/send/buy/restart/…) is owned by the daemon, applied by the HUD BEFORE
   acting. The comet flies to the button and parks there while KAIROS asks
   "Should I click Empty Trash?" — refusal answer `needs_confirm`; the model must
   re-call with confirm:true after a verbal yes.

Shared invariants with HeyClicky: element-index/label addressing ONLY (raw
coordinates don't exist in the protocol — the model cannot click blind),
per-PID event posting (no foreground theft), snapshot-act-verify (tool results
order a read_screen after every act).

## Pieces

- **Swift** `AXActor.swift`: press (AXPress → child-press → CGEvent.postToPid at
  frame center, AppKit→Quartz converted), setValue (kAXValueAttribute →
  focus + CGEventKeyboardSetUnicodeString one-shot typing), pressReturn.
  `AXMatch` now carries the live `node` + `pid` (nil on cached/fake matches).
- **Swift** `GuideModel.handleAct`: snapshot element addressing → resolve →
  confirm gate → comet flies to the element (420ms eye-arrival pause) → act →
  `act_result` over the guide_result channel. `DaemonClient` case `act_request`.
- **Daemon** `GuideBridge.requestAct` (12s window), `guideTools`:
  `click_element {element|find, app, confirm}` and
  `type_text {text, element|find, app, submit}` — self-heal open_app, lesson
  noteStepDone on KAIROS-clicks, ACT_PROTOCOL doctrine in descriptions.
- **Verifier**: act tools are LOCAL_TOOLS (our own; gated by our confirm regex,
  not the background approval gate). NEW phantom screen-action gate (every turn,
  utterance-independent, question-finals included): a final claiming
  highlight/click/type while NO screen tool SUCCEEDED → retryable flag. Grounded
  on result text ("Pointing at"/"Clicked"/"Typed into"), so failed calls don't
  license claims. This kills the live 2026-06-11 "I'm highlighting the Appearance
  section" (zero guide_user) fabrication class for good.
- **Tonight's session fixes folded in**: read_screen self-heals a not-running app
  (open_app + retry — the "guide verbally" dead-end is gone); described-not-pointed
  gate got a correction string (no more bare "Hmm — I'm not fully sure" as the
  whole answer to a teach ask).
- **Conductor**: click/type are SILENT_ACK_TOOLS (the model narrates each step
  itself); FRONT_ADDENDUM routes "DO something on their Mac" asks to [[task]].

## Mode split

- "teach me / show me how" → guide mode: point, the USER clicks, lesson persists.
- "switch to dark mode / do it" → act mode: KAIROS clicks, comet shows each step.
- Mid-lesson "just do it" → planner clicks; the click counts as a lesson step.

## Live E2E findings

- act r1: HUD silent on every request → **root cause was NOT the network**: the
  HUD's MAIN THREAD was permanently wedged inside MetalOrbView.tick() →
  CAMetalLayer.nextDrawable blocking on a starved drawable pool (screen lock
  stops compositing; the display link keeps acquiring). 1518/1519 samples in the
  semaphore wait. This retroactively explains EVERY "HUD isn't running" mystery
  of 2026-06-11 (the user's screen locked during background runs). Fixes:
  occlusion gate in tick() (skip frames when the window isn't composited,
  allowsNextDrawableTimeout), and the WS keepalive + watchdog moved OFF MAIN to
  DispatchSourceTimers on a private queue — the daemon link now survives any
  main-thread stall, and diagnosis logs keep flowing during one.
- act r2: transport fixed (0.2s reads) but the model POINTED on a DO ask and
  said "please click on that to proceed" — every tool-result breadcrumb steered
  to guide_user. Fixes: mode-aware breadcrumbs (open_app/read_screen/unchanged-
  screen texts now offer click_element-vs-guide_user by intent) + DO-MODE
  verifier gate (DO_ASK_RE imperative ask + pointed-or-told-user-to-click with
  zero successful click/type → retryable flag; confirm-pauses and HUD-down
  exempt).

- act r4: first real clicks — but AXPress on a System Settings SIDEBAR ROW
  returns .success WITHOUT navigating; the model click-looped blind and then
  claimed "You're all set" falsely. Fixes: (a) the matched node is the LABEL
  (AXStaticText) — AXActor now climbs to the actionable ancestor (row/cell/
  button) and SELECTS rows (kAXSelected, then container AXSelectedRows) instead
  of pressing them; (b) CHANGED-DETECTION in handleAct (pre/post inventory hash)
  feeds grounded verdicts into click results; (c) FALSE-DONE verifier check.
- `--axclick "Appearance" "System Settings"` dev probe = the whole act pipeline
  in 3s without the LLM loop. Probes proved: row selection navigates (CHANGED),
  Light/Dark presses flip the OS for real (defaults read confirms).
- Toggle nuance: button presses legitimately leave the inventory identical —
  verdicts are STRATEGY-AWARE (select → changed/unchanged; press/event →
  changed/pressed). Without this the model retried clicks that already worked.
- act r6–r7: turn 1 PERFECT twice (open → click Appearance CHANGED → click
  Light → OS = LIGHT, ~16s). Turn 2 kept finding new front-fabrication
  phrasings ("Switched your Mac back…", "Got it — switching it back…") →
  final structural cure: DETERMINISTIC ROUTING — a DO/TEACH/POINT ask can never
  be answered by the tool-less front (DO_ASK_RE/TEACHING_RE/GUIDE_RE on the
  UTTERANCE force [[task]]); claim-regexes remain as defense in depth.
- act r8: **FULL ARC VERIFIED** — "Switch my Mac to light mode" → clicked
  Appearance (changed) + Light (pressed) → OS=LIGHT in 17s; "Now switch it
  back" → forced [[task]] → clicked Dark → OS=Dark restored in 12s. Honest
  narration both turns. Zero fabrication.
